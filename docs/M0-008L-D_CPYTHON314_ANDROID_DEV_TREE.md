# M0-008L-D CPython 3.14 Android Dev Tree

## Headline

**C. DEVELOPMENT TREE REPRODUCTION BLOCKED**

The Android CPython 3.14 development tree could not be produced in this
environment. The blocker is concrete, diagnosed, and has an identified remedy.
It is not a fundamental obstacle, and it is not a claim that this is
impossible.

---

## 1. Exact CPython source revision

`https://www.python.org/ftp/python/3.14.0/Python-3.14.0.tgz`, matching what
Chaquopy 17.0 downloads in `target/python/build.sh`
(`wget -c https://www.python.org/ftp/python/$version_no_pre/$src_filename`).
The same file and build path that produced the OpenSSL artifact recovered in
M0-008L-B. VERIFIED FROM SOURCE.

## 2. Exact Android build procedure

The upstream procedure is CPython's `Android/android.py`, which Chaquopy calls
directly for Python <= 3.14:

```bash
python3.14 Android/android.py configure-host "$HOST"
python3.14 Android/android.py make-host "$HOST"
```

`Android/android-env.sh` documents the required inputs:

```sh
: "${ANDROID_HOME:?}"
: "${HOST:?}"
# You may also override the following:
: "${ANDROID_API_LEVEL:=24}"
: "${PREFIX:-}"
```

So the environment assumptions are: NDK via `ANDROID_HOME`, GNU target triplet
as `HOST`, **minimum API level 24**, and an install `PREFIX`. This milestone
used API 24 to match. VERIFIED FROM SOURCE.

## 3. What kind of tree is required

Answer: **B, a built install tree.** The CPython source checkout alone is not
sufficient, because `pyconfig.h` is *generated by configure* for the target
triplet and triplet-specific headers such as `pyconfig_aarch64-linux-android.h`
do not exist in the source distribution.

This milestone therefore ran `./configure` only, which is exactly the step
that produces the required generated headers, and stopped before `make`.

## 4. Header provenance

Intended: CPython 3.14.0 `Include/` plus configure-generated `pyconfig.h` and
`pyconfig_aarch64-linux-android.h`, all for host `aarch64-linux-android` at API
24.

**Not produced.** See section 10.

No host Python header tree was used as a substitute.

## 5. pyconfig.h relationship

CPython's generated top-level `pyconfig.h` includes the triplet-specific
header. On this host it produced:

```
checking host system type... aarch64-unknown-linux-android
```

so the expected include would be a `aarch64-*-android` path, not the host
Linux path seen in M0-008L-C. That substitution could not be verified because
the configure run did not complete. Nothing is claimed about the contents of a
`pyconfig.h` that was never generated.

## 6. libpython provenance

Not needed for this milestone's outcome, and not produced here.

For reference, the runtime library already available is Chaquopy's own
`libpython3.14.so` from the APK, which the pydantic-core probe links against
successfully. That library remains the intended link target; this milestone was
only about obtaining matching **headers**, not a different runtime.

## 7. PyO3 and CFFI configuration

From the M0-008L-C failure, the correct configuration requires:

- `PYO3_CROSS_PYTHON_VERSION=3.14`
- `PYO3_CROSS_LIB_DIR` pointing at an Android CPython 3.14 tree
- `PYO3_CROSS_PYTHON_IMPLEMENTATION=CPython`

`PYO3_CROSS_LIB_DIR` was absent in M0-008L-C, which is why pyo3 fell back to
discovering include paths from the host interpreter and produced
`-I /usr/include/python3.12`. That diagnosis stands.

## 8. Compiler include paths

Before the fix, from the M0-008L-C log:

```
-I /openssl/include          <- correct, Chaquopy OpenSSL 3.0.18
-I /usr/include/python3.12   <- host Ubuntu Python 3.12, wrong
```

This milestone's configure run correctly recognised the Android target but
never reached the point of emitting a header search path, so no replacement
path is claimed.

## 9. Host contamination before the fix

Confirmed and reproduced: the cryptography build was consuming
`/usr/include/python3.12/pyconfig.h`, which in turn includes
`aarch64-linux-gnu/python3.12/pyconfig.h`, a host-Linux layout. VERIFIED BY
BUILD, in M0-008L-C and unchanged here.

## 10. Build result - the first new blocker

Two attempts, both stopped at the first concrete blocker rather than stacking
fixes.

**Attempt 1:**

```
configure: WARNING: unrecognized options: --with-cc, --with-ld
checking host system type... aarch64-unknown-linux-android
configure: error: Cross compiling requires --with-build-python
```

The host target was correctly detected as `aarch64-unknown-linux-android`,
which confirms the Android build path was engaged. `--with-cc` and `--with-ld`
were removed and replaced with `CC` / `AR` environment variables.

**Attempt 2, the actual blocker:**

```
configure: error: "/usr/bin/python3" has incompatible version 3.12 (expected: 3.14)
```

**Root cause.** CPython 3.14 requires a **host CPython 3.14** as its build
interpreter in order to cross-compile. Chaquopy's own script reflects this: it
creates `cross-build/build/python` as a symlink to `python$version_short`, i.e.
it assumes a host `python3.14` exists on the build machine. The Ubuntu 24.04
container used here provides only Python 3.12.

This is a **build-environment prerequisite**, not a property of cryptography,
OpenSSL, or Android.

## 12. Remaining blockers and the identified remedy

The single blocker is: **no host CPython 3.14 available in the build
environment.**

Remedy, in order of cost:

1. Install a host CPython 3.14 in the build image. CPython's own cross-build
   CI does this, and `astral-sh/python-build-standalone` provides a
   reproducible CPython 3.14 for Linux x86_64, which is the same source `uv`
   uses. This is the correct fix and it is cheap.
2. Alternatively, run `Android/android.py` inside an environment that already
   has host CPython 3.14, exactly as Chaquopy's release build does.

Once a host 3.14 exists, `configure` should complete and emit Android-targeted
`pyconfig.h` and `pyconfig_aarch64-linux-android.h`, after which
`PYO3_CROSS_LIB_DIR` can point at that tree and the M0-008L-C build can be
retried.

## 13. Exact next step

1. Provision host CPython 3.14 in the build container (python-build-standalone
   or equivalent).
2. Re-run `configure --host=aarch64-linux-android --with-build-python=<host 3.14>`
   with the recovered OpenSSL tree, API 24.
3. Verify the generated `pyconfig.h` includes an Android triplet header and
   contains no host-Linux path. Stop if host Python still appears.
4. Assemble the header tree and set `PYO3_CROSS_LIB_DIR`.
5. Rebuild `cryptography` 50.0.1 unmodified, still on the shared OpenSSL 3.0.18
   route with `vendored` off.
6. Only once a `.so` exists, perform ELF acceptance, package integrity, the
   source/wheel/APK/device hash chain, and the device test.
